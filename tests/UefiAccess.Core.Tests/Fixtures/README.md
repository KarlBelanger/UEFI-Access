Fixtures are byte arrays built in code, not .bin files: `EnumerationBuffers.cs` assembles NtEnumerateSystemEnvironmentValuesEx (VARIABLE_NAME_AND_VALUE) buffers (three chained entries with a zero-length value and a non-ASCII name, plus a corrupted ValueOffset case), and `LoadOptionFixtures.cs` builds EFI_LOAD_OPTION records and every device-path node the formatter renders (Windows Boot Manager, USB stick, legacy BBS, PXE, truncated).
`SignatureListFixtures.cs` builds EFI_SIGNATURE_LIST bytes for the SignatureListReader and Secure Boot decoder tests; all three follow the UEFI 2.10 layouts, so offsets and lengths are right by construction.
`DcmRowFixtures.cs` is not bytes: it types Dell Command | Monitor rows (DCIM_BIOSEnumeration as WmiHelper.Query returns them) for the Dell settings tests, the 72 attributes of the A18 export as names, codes and value names only, with variants that change one thing each.
`CctkOutputFixtures.cs` is text: what Dell Command | Configure prints for one read option (the 5.2.2 and the legacy words, a line break, a synthetic banner, an empty output, two matching lines, and the line each option is expected to print for the A18 values), and the run outcomes the fallback's tests hand its provider; no process is started.
